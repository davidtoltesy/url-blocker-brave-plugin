# Glossary — Scheduled URL Blocker

Canonical terms for the concepts used in the knowledge base, mapped to the identifiers used in the code and the APIs.

## Product

| Term | Definition |
|---|---|
| **Blocked URL** | A domain/pattern entered by the user that the extension blocks. |
| **Time window** | A start and end point (hour:minute) during which the rule for a given URL is in effect. |
| **Blocking semantics** | Open decision: whether the extension should block *inside* or *outside* the interval. |
| **Schedule model** | Open decision: a global time window (current) or per-URL individual windows. |
| **Popup** | The settings interface shown when clicking the extension's icon. |

## Technical

| Term | Definition |
|---|---|
| **Manifest V3 (MV3)** | The current Chrome/Brave extension format; service worker-based. |
| **Service worker** | The JS process running in the background; here it performs the rule updates. |
| **DeclarativeNetRequest (DNR)** | API with which the browser (not JS) filters network traffic. |
| **Rule** | A `urlFilter` + `action` pair in DNR (e.g. `block`). |
| **Dynamic rule** | A DNR rule added at runtime from JS. |
| **Static rule** | A DNR rule predefined in the `rules.json` file. |
| **urlFilter** | The DNR pattern matcher; contains-based, and without anchors it can produce false positives. |
| **Anchor** | The `|` / `||` symbols in `urlFilter`, e.g. `||facebook.com`. |
| **Midnight crossing** | An interval that extends past midnight (e.g. 22:00–06:00); not handled in v1. |
| **Alarm** | The MV3 background scheduler; in v1 it refreshes the rules every minute. |
| **`chrome.storage.local`** | The persistent store for the `blockedUrls` list. |
| **`_metadata/` (artifact)** | An indexed ruleset byproduct generated by the browser; not part of the repo. |

## Process

| Term | Definition |
|---|---|
| **Code audit / review** | The examination of the existing code; for this project it was done on v1.0. |
| **Backlog** | The recorded items of future work (bug fixes, features); implemented only with approval. |
| **ADR (Architecture Decision Record)** | A recorded technical/product decision with reasons and alternatives. |
